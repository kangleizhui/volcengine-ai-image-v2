# 火山AI生图 — 图片生成 & 密钥交付

> Base URL = `http://{DOMAIN}:{PORT}`
> 测试密钥 = `{TK1}-{TK2}-{TK3}-{TK4}-{TK5}`（每IP每天10次）
> 注意：`{TK1}` 开头的是公共测试密钥，用户提供的其他格式密钥是其个人密钥，不要混淆。
> ⚠️ 密钥必须完整原样传入！

AI 通过调用后端 API 完成图片生成、套餐展示和密钥交付。技术细节见 `references/api-docs.md`，支付流程说明见 `references/payment-flow.md`。

## 核心能力

1. **文生图** — 输入文字描述，返回 AI 生成的图片 URL
2. **密钥查询** — 随时查任意密钥的剩余次数、到期时间和状态（`GET /api/key_info.php?key=XXXX`）
3. **套餐展示与密钥交付** — 展示套餐列表、创建订单、查支付状态、交付密钥

## API 调用流程

用户发来生图请求后，AI 执行：

1. 调用生图 API
2. **发文字消息**（生图结果描述，不夹带文件路径）
3. **下载图片**（从返回的 URL 下载到本地，用 `curl -sL -o /tmp/ai_img.jpg \"URL\"`）
4. **发送图片**（用 MEDIA 发送给用户）
5. 结束

### 调用生图

```http
GET /api/generate.php?key={测试密钥}&prompt={用户描述}&size=1920x1920&n=1
```

> 💡 默认后端使用 Seedream 生图模型，要求最小 **1920×1920**。管理员可在后台切换模型。
> 支持尺寸：`1920x1920`、`1536x1536`、`1024x1024`、`768x768`、`512x512`、`1920x1080`、`1080x1920`

### 密钥提示

每次生图后从响应 `data.key_info` 显示：
- 计次密钥 → `📊 剩余：X次`
- 测试密钥 → `📊 今日免费可用（每IP每天10次）`
- 时长/永久密钥 → 不显示剩余

## 获取密钥

- **免费试用** — 直接使用测试密钥 `{TK1}-{TK2}-{TK3}-{TK4}-{TK5}`，每IP每天10次
- **购买套餐** — 用户发送"套餐"查看可选方案，选择后 AI 下单并生成二维码图片
  1. `POST /pay/create.php` → 返回 `order_id` + `qr_code`
  2. 用 `qrencode -o /tmp/qr.png \"{qr_code}\"` 生成二维码，发给用户
  3. 提醒用户打开支付宝扫码支付，支付成功后告诉 AI
  4. 用户告知已支付后，AI 调 `GET /pay/query.php?order_id=xxx` 查状态
  5. 返回 `status=paid` → AI 做三件事：
     a. **把密钥发给用户** — "🎉 支付成功！你的密钥：`XXXX-XXXX-XXXX`，请保存好，后续可在其他设备使用"
     b. **自己配置好密钥**（key_manager 自动切换，后续调用都用这个付费密钥）
     c. **告诉用户已配置完成** — "✅ 已为你配置好密钥，现在直接发提示词给我就能生图了！"
  6. 返回 `status=pending` → 告知用户还未支付成功，请稍后再试

> ⚠️ 下单后必须生成二维码图片发给用户，禁止直接发支付宝链接。
>
> ⚠️ 如果创建订单失败，提示用户：当前API项目还未配置支付通道，请联系技能开发者配置。

## 🎨 模型自由选择

用户可查询可用模型并自由切换：

### 查询模型

```http
GET /api/volc_models.php
```

返回按类型分组的模型列表：
- 🖼️ **生图模型** — 可生成图片
- 👁️ **多模态理解** — 看图不能生图
- 💬 **文本对话** — 纯文本

AI 展示给用户看，让用户选择。

### 切换模型

调用生图时加上 `&model=` 参数即可覆盖默认模型：

```http
GET /api/generate.php?key={密钥}&prompt={描述}&model=doubao-seedream-5-0-260128
```

> 💡 不传 `model` 参数则使用管理员在后台设置的默认模型。
> 切换模型只影响当次调用，不影响其他用户。

## 🔑 密钥使用规则

1. **永远只有一个「当前使用的密钥」** — 不需要 PAID_KEY/FREE_KEY 双变量管理
2. **开始对话** → 用测试密钥
3. **用户买了套餐** → 查支付拿到新密钥后做三件事：
   a. **把密钥发给用户保存** — "请保存好，后续可在其他设备使用"
   b. **自己内部配置好**（key_manager 自动替换当前密钥）
   c. **告知用户已配置** — "直接发提示词给我就能生图了"
4. **调用失败（403 / 429）** → 按 `msg` 区分处理：
   - 次数已用完 → 引导购买套餐
   - 密钥无效/已过期 → 提醒用户检查
   - 429 → 测试密钥每日限10次已达上限
5. **密钥提示按 `key_info` 显示**
